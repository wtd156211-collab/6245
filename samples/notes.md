# 现场记录

随手记的，回头看能少走点弯路。

- 分析师那边的看板，点一下刷新要等二十分钟。查了一轮发现数据就那么几张表，一条查询过滤、投影、再聚合，
  没有窗口函数也没有嵌套视图，慢是因为每次刷新都把整张表从头算一遍。表还在长，与其加机器，不如把重算去掉。
- 口径是这次最花时间的：分组里最后一行被删掉之后，那一格到底该显示 0 还是干脆不显示？两边吵过一轮，最后按
  「不显示」定；但页面上不能直接抹掉，分析师拿它对数，卡片要留着标灰，并写上是第几步变空的。
- 有人提过「改完之后重新查一遍」的偷懒做法，被否了：变更平均每天几千步，每步都全量刷一遍等于没优化。
- 变更序列是运维从审计日志里导出来的，插入、更新、删除混在一起；有些步里同一张单子被改了两三次，也有刚落库
  当天又删掉的。变化要按「一步结束后的净效果」算，别按每条操作各算一次。
- 日志要求按水位回收：跑一整天下来只留最近两百步，不然内存先撑不住。
- 交付前对方强调过：同一份变更序列跑两遍，结果必须逐字相同；查某个客户的当前分组，开销不能随全表变大。
